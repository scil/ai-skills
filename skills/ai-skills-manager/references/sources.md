## Disputes on record

- **Frontmatter requiredness.** agentskills.io and the Anthropic platform docs: `name` and `description` required. Claude Code docs: all fields optional, `name` defaults to the directory. Both T1; the harness column wins for a skill that runs only in Claude Code, and the spec wins for a shared skill — every skill in this repository is shared, so the spec applies.
- **Description cap.** Spec and platform: ≤ 1,024 chars. Claude Code: truncates at 1,536 (description + `when_to_use`). Codex: no per-skill cap, a roster cap of 2 % of context / 8,000 chars, shortening all descriptions. Follow the tightest that applies: ≤ 1,024, key use case first.
- **`name` and the directory — resolved 2026-09-16.** The spec says `name` must match the parent directory and allows only `a-z`, `0-9`, `-`. This repository had written a `scil:` prefix into every `name` (commit `9bab03f`) to get a namespaced listing; the prefix is what Claude Code adds *itself* for plugin skills (`plugin-name:skill-name`, from `.claude-plugin/plugin.json` — see `claude-code-plugins-ref`), so the hand-written form would have doubled once packaged. Names were restored to the directory name and a root `.claude-plugin/plugin.json` with `"name": "scil"` added; Codex, which has no plugin namespace, sees plain names. Rule for the checklist: **a namespace is the harness's job; `name` is the directory name.**
