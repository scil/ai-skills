# Obsidian Console(中文说明)

给 AI 用的技能:在 Obsidian 里做一个"控制台"笔记——按钮按组分成 tab,每组一面按钮墙,点一下就跑项目仓库里的脚本。
本文是给人读的摘要;AI 实际读的是同级目录的 `SKILL.md`。按钮背后的接线(脚本、Shell commands 注册、`data.json`)归 `obsidian-vault-ops` 技能管。

## 由哪几块组成

- **控制台笔记**:最上面是按钮墙(一个 `dataviewjs` 块),下面是一句简介、需要选中文字的输入区、折叠的备忘。
- **按钮数据笔记**:每个 `## 分组名` 章节是一个 tab,里面一张「按钮 | 动作 | 颜色 | 说明」表格,表格下面是这一组的「点开」卡片。直接在实时预览里改格子,最后一格按 Tab 新增一行。
- **子分组**:tab 章节里写 `### 子分组名`,下面再放一张按钮表格和它自己的卡片,就会在同一个 tab 里分块显示(比如按硬件分:「PC + DJI 耳机」「小米摄像头」「不依赖硬件」)。没有 `###` 的 tab 和以前一样。
- **单步检查按钮**:除了端到端的按钮,流程里每个能单独验证的步骤(拍照、识别、录音、合成、播放、连模型)都各有一个按钮,按流程顺序排、按依赖的硬件分组;出问题时从上往下点,第一个不 ok 的就是坏的那一环。能产出中间文件的步骤(照片、音频)再配一个"用最新那份"的按钮,不用每次重新采集。
- **分组原则**:tab 按「想干什么」分(产品自己的功能 → 检查 → 评测 → 机器 → 设置与数据 → 链接,常用的在前)。「检查」只回答 ok / FAIL,用来找故障;「评测」给出数字和产生它的参数(有阈值的地方列出每个候选的得分),用来调参和对比——识别、打分这类结果总有好坏程度的步骤归评测;tab 里混了两类以上对象时,才用 `###` 按「操作的是什么」(某个硬件、服务、数据库、功能)分子组,按钮少、只有一类的简单 tab 不分。开和关放一起;功能自带的工具(编辑页、mock、试音)跟着功能走;卡片跟着它解释的按钮走(讲多个子分组的卡片放在第一个 `###` 之前,显示在 tab 顶部、所有框之外,标题写明覆盖哪几组),跨 tab 提到按钮时写明在哪个 tab。
- **卡片写法**:每张卡同一个样子——标题是这张卡回答的问题(结尾「(点开)」);第一行直接给答案(不加标签);每组有两张以上卡片时,在按钮下面收进一张折叠的「📖 说明 · N」大卡,打开后是一列问题标题;只有一张、或者卡片在 tab 内容区的末尾(下面没有按钮可挤)时直接显示;后面用粗体小标题分段、短条目,「症状 → 原因 → 怎么办」用表格;日期和"以前为什么这样"放最后一行 `**来历:**`。一件事只在一张卡里讲,别处写「X」tab 的【按钮】指过去;已退役的环境、过去的事故放控制台笔记的背景卡。
- **视图脚本**:库根目录 `_views/console-grid/view.js` 和 `view.css`,由 Dataview 运行;正本在本技能的 `assets/console-grid/`。

## 按钮怎么用

- 按钮墙由 **Dataview** 视图画出,分组成 tab,记住上次打开的那个;按钮数据和每个 tab 里的「点开」卡片都在按钮数据笔记里。点击交给 **Shell commands** 执行,**不弹黑窗**——结果以通知或弹窗形式回到 Obsidian 里。请在**阅读视图**下使用。
- 例外是要一直活着的服务(比如网页编辑界面):它会**另开一个真正的命令行窗口**,关窗口即停。
- **ⓘ 说明** 开关在 tab 栏最右边:打开后每个按钮下显示它真正执行的命令(`脚本` → 脚本里依次跑的命令);全局一个开关,重启 Obsidian 后保持。没把握时先打开说明扫一眼。
- 每个项目只有一个入口文件:仓库里的 `scripts\win\run_for_obsidian_console.ps1`。按钮表格的「动作」写的是一个 key(比如 `health`),点击时把 key 交给这个文件,由它决定跑哪个脚本;不认识的 key 什么都不跑。红、橙、黄色的按钮会先弹窗确认。
- Shell commands 里每个项目只登记「<项目> 控制台」和「<项目> 控制台(先确认)」两条(另有读取选中文字或要弹框填值的按钮各一条,也调用同一个文件)。找不到这条命令时,卡片变红并写明 `Command "…" not found`。
- 控制台本身不含任何逻辑——改命令请改仓库里的脚本,而不是笔记。
- 排版规矩:**按钮墙永远在最前面、露在外面,其余全部折在「(点开)」卡里**。仓库和文档的链接放在「常用文件」tab。
- 加一个新按钮只动仓库和笔记:加脚本 → 在 `run_for_obsidian_console.ps1` 里加一个 key → 在按钮数据笔记对应分组的表格里加一行。不用改 `data.json`,也不用退出 Obsidian。
- 老式控制台(一个个 Buttons 代码块)用 `type link`,链接是 `obsidian://shell-commands/?vault=…&_console_button=<key>&execute=<命令 id>`,走同一个文件。

## 已知限制

- Dataview 在库里有文件变化时会重画,已经展开的卡片会收起来;tab 和说明开关不受影响。
- 按钮数据没放在 frontmatter,因为属性面板改不了嵌套列表、看起来也费劲;表格最好看也最好改。
- 用重做的副本替换控制台之前,先比对正本在复制之后有没有被改过,把新改动合并进来。
