# Obsidian Vault Ops(中文说明)

给 AI 用的技能:在 Obsidian 仓库里写笔记、以及把笔记做成"能点按钮干活"的控制台。
本文是给人读的摘要;AI 实际读的是同级目录的 `SKILL.md` 和 `references/`。

## 为什么需要这个技能

写笔记本身很宽容,**接线不宽容**:

- 插件配置存在 JSON 文件里,而这个文件的所有权属于**正在运行的 Obsidian**——它会在下次保存时覆盖你写的内容。
- 按钮和命令之间靠**字符串精确匹配**,差一个字符就静默失效。
- 把用户输入的文字拼进 shell 命令时,**cmd 没有转义器**,`&` `|` `"` 会变成可执行命令。

这些坑不写下来,下次还会踩。

## 五条铁律

1. **每次重新定位仓库路径。** 用户会重组目录(项目文件夹、改名),记忆里的路径会写错地方。
2. **写插件配置前必须让用户完全退出 Obsidian。** 否则被内存里的设置覆盖。
3. **绝不把 `{{变量}}` 拼进 cmd 命令。** 用 PowerShell 或 sh,它们有真正的转义器。
4. **按钮的 action 必须与命令全名一字不差。** 用脚本逐条比对,不要靠眼睛看。
5. **插件的配置格式从 `main.js` 里提取,不要猜。** 猜错会把插件配置写坏。

## 高价值的 Obsidian 写法

- **可折叠 callout**(`> [!question]- 标题`)是长笔记里最有用的排版工具:自测题(问题露出、答案折叠)、
  速查表、按钮旁边的"这个输出怎么看"。
- **带锚点的双链**(`[[笔记#标题]]`)让控制台能精确指向解释,而不是甩一整篇文档过去。
- **加配套笔记时,两边都要加链接**,单向链接会烂掉。
- `file:///` 链接里的中文和空格**必须百分号编码**,否则点了没反应。

## 接线的设计取舍

- **按钮调用仓库里的脚本,不要把命令内联进 vault 配置**——否则项目一改,配置就悄悄过时。
- **每条命令都必须能自己结束。** `docker logs -f` 这类会永远跑不完,要另写有界版本。
- **危险操作加二次确认**(停服务、删数据、会在家里发出声音的)。
- **输出按体量分流**:一两行用通知,报告用弹窗。
- **让用户输入文字**,优先用"笔记当输入源"(选中文字 → 点按钮),而不是弹框:内容能存下来、能反复改、能一眼看到。

## Windows 脚本的三个坑

1. `.bat` 结尾的 `pause` 在无控制台环境会卡死 → 调用时加 `< nul`。
2. 带中文的 `.ps1` **必须存成 UTF-8 BOM**,否则 `powershell.exe` 按 ANSI 读,中文全乱、报一堆莫名其妙的语法错。
3. 传任意文本时**绕开 `.bat`** 直接调目标程序,否则 bat 那层又把 cmd 解析引回来了。

## 这些经验的来源

2026-08 在 Carema-Kis-AI 项目里,为一套家用摄像头 AI 系统搭 Obsidian 控制台时,逐条踩出来的。
其中"cmd 没有转义器"是读 Shell commands 插件源码时发现的——作者在那行代码旁边写了个 `:'(`。
