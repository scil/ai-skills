# AI-agent research

Read this when the question or the claims are about AI coding agents or LLMs: agent instruction files (`AGENTS.md`, `CLAUDE.md`), prompting guidance, skills, a model's or an agent's behaviour, studies of agents on software tasks. It adds agent-specific corpora, scope fields and traps to the general method; the tiers and verdicts stay as in `source-tiers.md` and `verdict-protocol.md`. Origin: the `ai-agents-md` research of 2026-09-15 (see `readme.md`).

## 1. Corpus by claim type

| Claim is about | Search first (T1) | Then | Notes |
|---|---|---|---|
| What a vendor recommends for its model or agent | The vendor's own documentation property that owns the topic: product docs (e.g. Claude Code docs) vs platform/API docs (e.g. Anthropic's prompting pages per model) vs cookbook vs changelog | The vendor's engineering blog (T4 with weight) | Name the property before the verdict (§3.1). |
| How a vendor's team works ("OpenAI keeps AGENTS.md short") | The team's own post or talk that the sentence came from | The vendor's public repositories | A post about an internal repository is not contradicted by a public one (§3.2). |
| A file "in" a repository (a canonical example, a layout) | The repository itself: `api.github.com/repos/<owner>/<repo>/git/trees/<branch>?recursive=1`, the raw file | Articles describing it (T4) | One API call settles existence (§3.3). |
| An instruction-file format or convention | The format's own specification site and the agent vendors' docs that read it | Exemplars (T3) | Each agent reads the file its own way; record per vendor where they differ. |
| A measured effect of agents or instruction files | Peer-reviewed or preprint studies (T2), with scope fields (§2) | Vendor evaluations (T4 with weight) | Studies disagree along scope lines; never let one study decide. |
| A model's capability, limit, price or ID | The vendor's model and pricing pages on the day of checking | Release posts (T4) | Fast-moving: `gate-days` 7. |

## 2. Scope fields for an agent study

Record these, in addition to `source-tiers.md` §2, before the findings:

- **Agents and models tested**, with versions and dates; results on one model generation do not transfer to the next.
- **Languages and task type**: bug fixes from issues, feature work, small PRs under N lines, benchmark vs real repositories.
- **Input provenance**: instruction files generated by an agent vs written by developers; repositories with or without existing documentation.
- **What was measured**: task success or correctness, cost (which tokens), time, behaviour counts; a study with no correctness check cannot speak to quality.

## 3. Traps and the rule for each

1. **A vendor has several documentation properties.** A claim called *not found* after searching Claude Code's docs was stated in Anthropic's platform prompting docs (the "avoid 'always double-check'" advice for Opus 5 and Fable 5). Name the property searched in the verdict.
2. **A team's post is not the organisation's repository.** "OpenAI keeps AGENTS.md around 100 lines" came from a post about an internal repository; checking it against the ~550-line public `openai/codex/AGENTS.md` gave a false CONTRADICTED. Verdict: WRONG OBJECT.
3. **Blog-described exemplars may not exist.** A "canonical CLAUDE.md" that several blogs recommended was absent from the repository's 1,592-entry tree. Verdict: INVENTED, with the tree listing as evidence.
4. **One study is not the research.** Seven studies of instruction files disagreed exactly along their scope fields; the user ruled that a single study carries too little weight and that the vendors' own documentation leads. Report the split with the field that explains it.
5. **Guidance is per model generation.** Vendors write prompting advice per model (the "always double-check" advice in §3.1 is on the Opus 5 and Fable 5 pages). Record the model and the page's date with each rule, and re-check vendor guidance at `gate-days` 7 before reusing it.
6. **Chat transcripts are T4.** A transcript or another agent's answer is a set of claims to verify, not a source; register each claim's real source.

## 4. Registering the result

Skills and instruction files that rest on this research keep a sources registry (`templates/sources.md`) checked by `ai-agents-md/scripts/check-sources.ps1`; vendor rows use `gate-days` 7.
