# 隐喻提取

一套将产品名称（或核心概念）转化为完整设计语言的方法。当产品名称中包含空间性、感官性或生活化隐喻时使用，挖掘它在视觉和交互逻辑上的潜力。

## 为什么隐喻很重要

只停留在营销文案层面的隐喻是浅薄的。当隐喻驱动功能命名、文案撰写、视觉元素和交互模式时，它才成为产品的**统一逻辑**。用户会感受到这种连贯性，即使说不出原因——每个页面都在强化其他每个页面。

相反，一个产品名称里有隐喻，却没有将它延伸到设计中，就是在浪费自己最强的资产。ThanksPorch 可以是一个起了个可爱名字的通用资源共享 App，也可以是一个让用户真切感受到自己站在门廊上的产品。下面这套方法论会产生第二种结果。

## 提取流程

### 第一步：盘点物理属性

列出隐喻的所有具体属性——实物、感官特质、社会惯例、时间规律。不要过滤，目标是 15 条以上。目的是积累原材料。

ThanksPorch 的盘点包括：

- 一扇门（通往私人空间的入口）
- 一个门槛（公共与私人的边界）
- 一盏门廊灯（标志欢迎/可用状态）
- 一道栏杆（界定空间，可以倚靠聊天）
- 纱窗（让空气透进来，视线半透）
- 木质地板（磨损、踩踏、熟悉感）
- 门垫或欢迎垫
- 椅子或长椅（暗示坐下、逗留）
- 盆栽植物
- 门牌号/地址
- 放在门口的邮件或包裹
- 放给别人的东西（一碗糖果、一堆免费物品、菜园里的蔬菜）
- 街上路过的邻居
- 季节性天气（门廊半室内半室外——季节很重要）
- 一天中的时段（傍晚的灯光，下午的阳光）
- 敲门声
- "顺路拜访"的惯例
- 夏天的柠檬水
- 门廊朝向街道而非后院的方式
- 节日装饰

### 第二步：将物理属性映射到产品概念

对每个物理属性，问：*这对应哪个现有或潜在的产品概念？* 有些会直接对应，有些会激发新功能创意，有些找不到映射（直接丢弃）。

ThanksPorch 的示例映射：

| 物理属性 | 产品概念 |
|---|---|
| 门 | 进入私人资料页/设置 |
| 门槛 | 半公开可见度（Porch Visible）——不是街道，也不是客厅 |
| 门廊灯 | 用户在线状态（亮 = 可接受请求，暗 = 暂不可用） |
| 栏杆 | 界面中的分区分隔线 |
| 纱窗 | "受限可见性"状态的视觉纹理（可见但不可进入） |
| 门牌号 | 专属 Porch 邀请链接/二维码 |
| 放出来的东西 | 正在共享的资源/物品 |
| 路过的邻居 | 传递链——经过你门廊继续向前的访客 |
| 敲门 | 发起一个请求 |
| 时段/季节 | 可用时间窗口（effectiveAvailability） |
| 朝向街道 | 半公开立场——对路过的人可见，但不在全网被检索 |

这张表成为产品的**概念骨架**。命名功能、撰写文案或设计视觉时，随时参照。

### 第三步：从映射中推导文案

用映射好的概念生成具体的界面文案。隐喻为你提供了通用 SaaS 产品无法复制的专属动词、名词和短语。

基于上面的映射：

- "提交请求" → "在门廊留一张便条"
- "可接受请求" → "门廊灯亮着"
- "暂时不可用" → "今天在里面"
- "待处理请求收件箱" → "谁来访过"
- "分享链接" → "把你的门廊地址给他们"
- "公开市场"（被拒绝的概念）——明确不是这个，因为门廊朝向街道，但不是街道本身

如何将这些整理成完整的替换表，见 `vocabulary-system.md`。

### 第四步：从映射中推导视觉元素

从中挑选 3–5 个物理元素，作为反复出现的视觉元素（motif）。**克制使用**——过度使用会稀释意义。这些 motif 应该出现在特定的、语义明确的位置，而不是到处装饰。

ThanksPorch 的规划：

| 视觉元素 | 出现位置 | 原因 |
|---|---|---|
| 门廊灯（小圆光点） | 用户在线状态指示器 | 直接语义匹配——灯 = 欢迎 |
| 栏杆纹（横向条纹） | 内容区域之间的分隔线 | 呼应身处门廊的空间感 |
| 纱窗纹理 | "受限可见性"卡片的背景 | 视觉传达"可见但无法进入" |
| 木纹（极淡） | 仅用于门廊首页背景 | 在用户停留时间最长的地方强化空间隐喻 |
| 手写体 | 仅用于感谢时刻 | 呼应在门上留便条的惯例 |

"这个 motif 只出现在这个位置"的克制原则，正是赋予每个 motif 分量的原因。门廊灯图标出现在每个页面就变成了装饰；门廊灯图标只出现在在线状态开关上，就变成了意义。

## 适用于其他产品名称

同样的流程适用于任何具有隐喻的产品名称。几个快速示例：

**Hearth**（假想的家庭沟通 App）：
- 物理属性：火焰、向外辐射的温暖、围坐在一起、余烬、拨弄火堆、壁炉边的聊天、壁架、壁架上的照片
- 映射：家庭成员的在线感 → 头像周围的光晕强度；存档的记忆 → 壁架；最近的对话 → 火（活跃）；旧的对话 → 余烬（仍然温热但更安静）；"重新激活" → 把一条消息推回顶部
- 视觉：暖琥珀色光晕，余烬渐灰的时间轴可视化，相框作为记忆容器

**Lantern**（假想的心理健康日记 App）：
- 物理属性：黑暗中的光，用手提着，燃料储量，明暗变化，投下的阴影，照亮前路
- 映射：坚持日记 → 燃料量；困难的日子 → 光线暗，轻松的日子 → 光线亮；私密记录 vs 分享的记录 → 盖上的 vs 打开的灯笼
- 视觉：暖黄色光晕，深色模式优先（灯笼在夜晚工作），柔和的渐隐动画

**Doorstep**（假想的邻里互助 App）：
- 物理属性：室内外之间的地方，放东西、发现东西，短暂出门，欢迎垫
- 映射：与 Porch 非常相似，但规模更小——强调快速帮忙而非持续关系

流程始终是：**盘点 → 映射 → 推导文案 → 推导视觉**，顺序不变。

## 需要避免的误区

- **不要强迫每个属性都找到映射。** 有些物理属性没有有用的产品对应。直接丢弃。强行映射会产生牵强的功能。
- **不要让隐喻变得字面化。** 一个到处是木纹纹理的拟物化 porch 应用，比一个在文案和几个关键 motif 中运用隐喻的简洁应用更糟糕。隐喻应该被感受到，而不是被描绘出来。
- **不要让隐喻锁死必要功能。** 如果用户需要一个设置页，他们就需要设置页——可以叫"门规"或者就叫"设置"，但不要因为门廊没有设置面板就拒绝建这个功能。
- **不要过度使用 motif。** 5 个 motif 各用于 5 个特定位置，好过 5 个 motif 用在所有地方。稀疏感才能赋予每个 motif 意义。
- **不要混用隐喻。** 如果产品叫 Porch，就不要引入无关的隐喻（篝火、图书馆等）。一个被充分挖掘的隐喻，好过三个被浅尝而止的隐喻。

## 这个阶段的输出物

完成这个流程后，应该有三份产出物：

1. **物理属性盘点**（15 条以上）
2. **概念映射表**（物理 → 产品，约 10 行）
3. **视觉 motif 规划**（3–5 个视觉元素，附带明确的出现位置规则）

这三份产出物直接输入词汇体系（下一个参考文件）和风格指南。
