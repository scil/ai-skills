# 设计令牌

一种将风格指南实现为**单一文件中的 CSS 变量**的模式，使整个产品可以通过编辑一个文件来重新换主题。对温情产品来说这至关重要，原因有三：

1. 你还不确定自己的样式决策是否正确——你希望能在以后进行 A/B 测试或替换，而不用重写每个组件。
2. 温情产品通常需要**用户可自定义的主题**（产品本身支持每个用户或每个 Porch 的主题定制）。
3. 与 AI 工具协作时需要令牌文件作为权威来源——没有它，每个生成的组件都会风格漂移。

## 结构

### 选项 A：单一令牌文件（最简单）

```css
/* tokens.css */
:root {
  /* 品牌色 */
  --color-primary: #7A9E82;
  --color-primary-light: #C4D9C8;
  --color-primary-dark: #4A6E52;

  --color-accent: #C4805A;
  --color-accent-light: #E8C4AD;

  /* 表面色 */
  --color-background: #FAF7F2;
  --color-surface: #F0EAE0;
  --color-border: #D4C5B0;

  /* 文字色 */
  --color-text: #2C2416;
  --color-text-muted: #7A6E5F;
  --color-danger: #B85C4A;

  /* 字体 */
  --font-heading: 'Lora', serif;
  --font-body: 'DM Sans', sans-serif;
  --font-handwrite: 'Caveat', cursive;

  /* 圆角 */
  --radius-sm: 6px;
  --radius-md: 14px;
  --radius-lg: 20px;

  /* 阴影 */
  --shadow-card: 0 1px 4px rgba(44, 36, 22, 0.06);
  --shadow-lifted: 0 4px 16px rgba(44, 36, 22, 0.10);
  --shadow-float: 0 12px 40px rgba(44, 36, 22, 0.14);

  /* 间距 */
  --space-xs: 4px;
  --space-sm: 8px;
  --space-md: 12px;
  --space-lg: 16px;
  --space-xl: 24px;
  --space-2xl: 32px;
  --space-3xl: 48px;
  --space-4xl: 64px;

  /* 行高 */
  --line-body: 1.7;
  --line-tight: 1.3;
}
```

在应用根部引入这个文件一次。每个组件都使用 `var(--color-primary)` 等——永远不用硬编码值。

### 选项 B：多主题文件（用于主题切换）

```
styles/
  tokens.css        ← 引入当前活跃主题
  themes/
    warm.css       ← 门廊示例的默认温情主题
    minimal.css    ← 备选的更简洁主题
    dark.css       ← 深色模式变体
    organization.css ← 供组织使用的 Porch 主题
```

`tokens.css` 引入当前活跃主题：

```css
@import './themes/warm.css';
```

要切换全局主题，只需改变引入的文件。要支持每用户主题，可以在运行时切换引入（见下方的选项 C）。

### 选项 C：运行时主题切换（用于产品内置主题选择器）

这个模式允许用户（或管理员）无需重新构建即可切换主题。在 `<html>` 或 `<body>` 上设置 `data-theme` 属性：

```css
:root,
[data-theme="warm"] {
  --color-background: #FAF7F2;
  --color-primary: #7A9E82;
  /* ... 其余 warm 主题变量 */
}

[data-theme="minimal"] {
  --color-background: #FFFFFF;
  --color-primary: #3B82F6;
  /* ... 其余 minimal 主题变量 */
}

[data-theme="dark"] {
  --color-background: #1C1C1E;
  --color-primary: #9DBBA3;
  /* ... 其余 dark 主题变量 */
}
```

在运行时切换：

```javascript
document.documentElement.setAttribute('data-theme', 'minimal');
```

如果产品本身支持用户自定义主题（例如用户可以选择自己门廊的配色，组织可以设置品牌主题），就用这个方案。

## 组件编写规则

令牌存在后，编写任何组件时**强制执行这些规则**：

1. **不硬编码颜色** — 组件 CSS 中的每个颜色值都必须是 `var(--color-*)`。可以用 Lint 规则强制执行。
2. **不硬编码字体** — 每个 `font-family` 都必须是 `var(--font-*)`。
3. **不硬编码圆角/阴影** — 同样的规则。
4. **间距可以用 `var(--space-*)` 也可以用 rem** — 对于温情相关的间距（卡片内边距、区块间隔）优先用令牌名称；一次性的布局调整用 rem 也可以。
5. **计算中使用的数字（z-index、透明度、动画时长）可以是原始值**。

原因：任何影响产品**温情感受**的值（颜色、字体、圆角、阴影、表面间距）都必须是可主题化的。功能性值（z-index 等）不承载温情感受，所以可以是原始值。

## 在不同框架中的文件位置

### Next.js（App Router）

```
src/
  app/
    globals.css     ← 引入 tokens.css
  styles/
    tokens.css
    themes/
      warm.css
```

在 `globals.css` 中：
```css
@import '../styles/tokens.css';
```

### Vite / React

```
src/
  styles/
    tokens.css
  main.tsx          ← 引入 './styles/tokens.css'
```

### Tailwind v3+（如果使用 Tailwind）

Tailwind 可以通过 `theme.extend` 消费 CSS 变量：

```javascript
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        primary: 'var(--color-primary)',
        accent: 'var(--color-accent)',
        background: 'var(--color-background)',
        surface: 'var(--color-surface)',
      },
      fontFamily: {
        heading: 'var(--font-heading)',
        body: 'var(--font-body)',
      },
      borderRadius: {
        sm: 'var(--radius-sm)',
        md: 'var(--radius-md)',
        lg: 'var(--radius-lg)',
      },
    },
  },
};
```

这样可以同时拥有 Tailwind 的开发体验和令牌的主题化能力。

### Tailwind v4

Tailwind v4 通过 `@theme` 原生支持 CSS 变量：

```css
@theme {
  --color-primary: #7A9E82;
  --font-heading: 'Lora', serif;
  /* ... */
}
```

然后在类名中直接使用 `bg-primary`、`font-heading`。

## 字体加载

将令牌决策与正确的字体加载配合使用。Google Fonts 方式：

```css
/* 在 tokens.css 或单独的 fonts.css 中 */
@import url('https://fonts.googleapis.com/css2?family=Lora:wght@400;500&family=DM+Sans:wght@400;500&family=Caveat:wght@500;600&display=swap');
```

或在 Next.js 中使用 `next/font`：

```typescript
import { Lora, DM_Sans, Caveat } from 'next/font/google';

const lora = Lora({ subsets: ['latin'], weight: ['400', '500'], variable: '--font-heading' });
const dmSans = DM_Sans({ subsets: ['latin'], weight: ['400', '500'], variable: '--font-body' });
const caveat = Caveat({ subsets: ['latin'], weight: ['500', '600'], variable: '--font-handwrite' });
```

然后在根元素上应用这些变量，让它们层叠进 tokens.css。

## Lint 和代码审查

在较大的代码库中，为防止风格漂移，添加 Stylelint 或 ESLint 规则，禁止在组件文件中出现硬编码的颜色/字体值：

```javascript
// stylelint 配置
"declaration-property-value-disallowed-list": {
  "/^color/": ["/^#/", "/^rgb/"],
  "/^background/": ["/^#/", "/^rgb/"],
  "font-family": ["/^[A-Z]/"]  // 禁止裸字体名称
}
```

这会强制每个贡献者使用令牌。

## 令牌版本管理

将令牌文件视为有版本的产出物：

- 在设计任何页面之前就提交它
- 不要随意更改令牌值——它们会级联到每个组件
- 更改值时要有意识地进行，并审查受影响的页面
- 如果要进行主题实验，保留旧的主题文件（warm-v1.css、warm-v2.css）

原因：改变一个令牌可以同时改变 100 个页面的情感感受。这是个特性，但也意味着改动值得认真对待。
