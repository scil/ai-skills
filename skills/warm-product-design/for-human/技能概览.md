# 温情产品设计

一套专为**人与人之间情感连接**为核心价值的产品而设计的方法论，而非面向交易效率。基于一款以门廊命名的感恩产品的实践提炼，但可推广至任何以温情、信任和人情味为差异化竞争力的产品。

## 这套技能存在的原因

现代 App 的默认设计模式（白色背景、Inter 字体、蓝色主按钮、"提交"/"取消"文案、角标计数推送通知）来自 SaaS 和电商产品，它们以清晰和转化率为优先目标。对于温情型/关系型产品而言，这些模式会主动**破坏价值**——它们让产品感觉像一个平台而不是一个地方，像一笔交易而不是一段关系。

为这类产品做好设计，需要的是一套不同的方法论，而不仅仅是换一套配色。本技能正是对这套方法论的系统化记录。

## 适用场景

当产品具备以下至少一个特征时，应用本技能：

- **情感核心**：信任、关怀、感恩、归属感、互助、家庭、信仰、邻里关系
- **真实关系**：用户在线下已有连接，或产品旨在加深线下连接
- **空间/感官命名**：产品名称暗示某个实体场所或物品（Porch、Table、Hearth、Lantern、Garden、Doorstep、Letter、Kitchen 等）
- **反市场化定位**：明确不是市场平台，不是公开的，不是交易性的
- **低频但高意义**：用户不会每天打开，但每次打开都很重要

如果产品是生产力工具、数据面板、电商平台或通用工具，本技能不适用——改用通用前端设计方法。

## 方法论——五个阶段

按顺序执行，每个阶段建立在前一个阶段之上。跳过阶段（例如，在定义情感反模式之前就选色彩）会产生混乱的结果。

### 阶段一：诊断情感核心

在做任何视觉决策之前，先用文字回答四个问题：

1. **这个产品应该给人什么感觉？** 给出 4–6 个感官或情景关键词（例如"周日下午"、"一封手写信"、"夏夜门廊上亮着的灯"）。目标是具体的物理情景，而不是"现代感"或"值得信赖"这样的抽象形容词。
2. **这个产品不应该给人什么感觉？** 同样要具体（例如"Amazon"、"医院入院表格"、"晚上 11 点的 Slack 通知"）。反模式和正模式同样重要。
3. **用户在情感时刻是什么状态？** 不是他们的人口统计特征——而是他们的心理状态。（"刚刚得到帮助、想表达感谢但不知道怎么开口的人"是一个真实的答案；"一线城市的千禧一代"不是。）
4. **产品的单一情感高潮是什么？** 那个如果做好了就让产品值得存在的时刻。（门廊示例的答案：分享者得知自己的给予被接收、且真的有意义的那一刻。）

将答案整理成一页"情感简报"文档。之后所有决策都要参照这份文档。

### 阶段二：提取隐喻

如果产品名称中包含空间或感官隐喻，**系统化地挖掘它**。隐喻是现成的设计语言——不要浪费它。

完整流程见 `references/metaphor-extraction.md`，简版如下：

1. 列出隐喻的物理属性（门廊有：一扇门、一个门槛、一盏灯、一道栏杆、纱窗、季节性天气、临街的视角、路过的邻居）。
2. 对每个物理属性，找到它对应的产品概念（门廊灯 → 用户在线状态；门槛 → 半公开的可见度；路过的邻居 → 传递链）。
3. 用这些映射来命名功能、撰写文案、选择视觉元素。

隐喻地图成为整个产品的统一逻辑。用户会感受到这种连贯性，即便说不清楚原因。

### 阶段三：建立词汇体系

最具杠杆效应的设计干预是**用关系型语言替换事务型语言**。这不需要任何成本，无需修改代码，却能彻底改变用户体验每个页面的情感感受。

完整的替换模式见 `references/vocabulary-system.md`，简版：

- "提交请求" → "轻声询问"，或隐喻专属版（"在门廊留一张便条"）
- "接受" / "拒绝" → "是的，它是你的" / "这次不行，也许下次"
- "你有 3 条待处理请求" → "3 位邻居来访过"
- "用户资料" → "他们的门廊" / "他们的角落"
- 空状态：永远不要说"你还没有添加任何内容！"——发出邀请，不要施压

规则：在**情感时刻**（按钮、通知、空状态、感谢页、欢迎界面）使用关系型语言；在表单字段和设置等功能性区域保持普通语言。这种对比正是让温情时刻感觉温情的原因。

### 阶段四：定义设计系统

现在才开始做具体的视觉决策。建立一份完整的风格指南，涵盖：

- **颜色**：暖色调调色盘，附带理由（永远不只是色值——每个选择都有情感理由）
- **字体**：通常三档——衬线体增加标题温度、人文无衬线体用于正文、手写字体用于情感高峰（克制使用）
- **圆角**：有机感，不要玩具感（卡片通常 14–20px）
- **阴影**：暖色调（用产品文字色作为阴影底色，而非纯黑/冷灰）
- **间距**：充裕；默认比感觉需要的留更多留白
- **图标**：仅用描边图标，不用填充——描边看起来像手绘，填充像企业标配
- **摄影指引**：自然光、暖色调、手持物品、有纹理的背景（绝不用白底产品图）
- **三个明确的反模式**，具体到此产品

完整模板和理由见 `references/style-guide-template.md`。

### 阶段五：实现为可切换的设计令牌

在写任何页面之前，先将设计系统以 CSS 变量的形式写入一个文件。然后所有页面只使用 `var(--令牌名)` ——绝不硬编码颜色或字体。

这让整个产品后期可以一键换主题（修改单个文件即可重新定义品牌），同时避免使用 AI 工具时出现风格漂移——所有生成的组件因为被令牌约束而保持一致。

实现模式见 `references/design-tokens.md`。

## 配合 AI 工具使用

本方法论设计为可借助 AI 协作执行（Claude 负责思考，v0/Figma AI 负责生成）。工作流：

1. 用 Claude 撰写情感简报、隐喻地图和词汇替换表
2. 用 Claude 起草设计令牌 CSS 文件
3. 对每个发给 v0/Figma AI 的生成请求：
   - **始终在提示词前粘贴完整令牌文件**
   - 在写任何功能说明之前，先写**情感脚本**（用户在这个页面的情感是什么）
   - 禁止 AI 硬编码任何颜色、字体或圆角值

提示词模板和工作流见 `references/ai-prompting-workflow.md`。

## 页面优先级——情感权重

不同页面承载的情感权重不同。时间有限时，优先设计那些情感设计对产品成败影响最大的页面：

| 页面 | 为什么最重要 |
|---|---|
| 邀请落地页 | 新用户的第一印象——他们来这里是因为一个真实的人，不是一个品牌 |
| 空状态 | 新用户决定是否值得投入的地方 |
| 发起请求的对话框 | 产品中心理门槛最高的动作——开口求助 |
| 感谢/感恩时刻 | 情感高潮——让用户愿意回来的原因 |
| 通知 | 体量小但频繁出现——语气漂移的最大来源 |

先把这五个设计好，其他什么都别急。一个完美的 Dashboard 配上事务型的感谢页会失败。一个粗糙的 Dashboard 配上漂亮的感谢页会成功。

## 常见失败模式

在 AI 输出或自己的草稿中发现以下问题时，立即拒绝：

- **纯白背景**（#FFFFFF 或 #F5F5F5）——瞬间摧毁温情感。改用奶油色/带黄色调的米白。
- **冷灰阴影**（`rgba(0,0,0,...)`）——让卡片感觉漂浮在虚空中。改用暖色调阴影。
- **首字母大写的按钮文字**（"Submit Request"）——像企业表格。改用句子大小写，温情产品还可以用小写隐喻文案。
- **计数通知**（"3 条新消息"）——像任务队列。改为"X 个人在等你"之类的表达。
- **填充图标**——显得企业化、盖章感。全部换成描边图标。
- **通用的"注册后继续"**流程——第一个动作应该由邀请用户的那个人驱动，不是由产品驱动。
- **AI 烂大街字体**（Inter、Roboto、Space Grotesk）——过度使用，情感上毫无特色。选有个性的字体组合（如 Lora + DM Sans + Caveat）。
