# explain — where the rules came from

Written on 2026-10-24 in a Leafi session as `explain-by-analogy`, renamed `explain` the same day so further explanation methods join `methods/` as arguments; Reader and Ground are shared by every method. The owner pasted a prompt for explaining a complex mechanism by analogy; a review tightened it, then the owner pointed out that the reader of an AI-written system may not know the system either.

- **Observable scene first, internal names second**: the original prompt assumed the reader knew the system's own words. For a system an AI wrote, what the reader knows is its outside behaviour, so the scene starts there and the mapping table gained the "What you observe" column.
- **The table covers what later steps use**: the original asked for rows only for elements "just mentioned", which contradicted the walk, whose failure and fix bring new actors.
- **Relations, not names**: an analogy whose names line up but whose order or waiting does not misleads more than none; hence "preserve relations" and the fallback to no analogy.
- **`ground` is an argument**: the prompt first lived as two near-identical Espanso snippets, with and without the code-reading step; it moved here so each snippet is one line naming this skill.

## The other five methods

Added the same day from five prompts the owner pasted (a blend of the Feynman technique, everyday analogy, layered explanation, a traced example and teach-back), reviewed before absorbing:

- **Naming**: the pasted "Feynman" prompt was the agent explaining in layers; the Feynman technique is the learner explaining and finding gaps. So the layered prompt became `layers` and the learner-explains prompt `teachback` (the education term).
- **`layers`**: three fixed levels (child, junior, expert) tripled the length and repeated itself; now plain then precise, with an expert depth only for a hidden trade-off. "3 misunderstandings" invited invented ones: now up to 3, each tied to what suggests it. Check questions test transfer, and get graded when answered. Its analogy table points at `analogy` step 3 instead of a weaker copy.
- **`trace`**: "what is written to the database" generalised to side effects; variable values must come from a test, fixture, log or run, else "(inferred)"; the risky step needs a reason; trivial calls merge. A Leafi scenario example was dropped from the shared skill. Tracing needs the code, so it always grounds.
- **`socratic`**: added a diagnostic start (what the reader knows), a hint ladder with a cap of three misses, a checkpoint per mastered idea instead of every 5 questions, and an end condition.
- **`teachback`**: findings ranked (wrong, vague, skipped, undefined), checked against code with `ground`, and repeated on each revision until clean.
- **`diagram`**: kept the 5-box cap and the failure redraw; added what was left out, what sends each arrow, and what the reader would observe in the failure.
- **Two older Espanso prompts merged in**: `xb ;` (explain for a beginner) into `layers`, `draw ;` (interactive call-order diagram) into `diagram`; both triggers now call this skill. From `xb ;`, `layers` kept the rule that pays off most: write for a reader who has forgotten the session (self-contained, no session-local names); plus background in the problem step, one concrete scenario with a code example in the precise depth, and a closing glossary with English forms. From `draw ;`, `diagram` gained an optional call-order view (grounded; plain gloss per name; code excerpt per key step) and an interactive page; the vague "animate the complex parts" became stepping one arrow at a time, the only motion. Later the same day the owner made the cheapest run the default: `diagram` does only the 5-box picture and its arrows unless asked for more, so `draw ;` is the basic trigger, `draw-seq ;` the call order alone, `draw-all ;` everything. A review of the 5-box cap kept it (working memory holds about four chunks, Cowan 2001) and added what a static box picture lacks: numbered arrows for the order of one run, a marked entry where the reader's action comes in, and zooming into one box (the C4 model's levels) instead of a sixth box.
- Dropped as no-ops: "define every term before using it" (the global instruction file says so); "no simply or basically" became the positive "plain, concrete words" in Reader.
