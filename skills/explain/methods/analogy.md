# Analogy

Reach the analogy from the reader's real scene and map it role by role. With `ground`, the [Ground](../SKILL.md#ground) step runs first.

1. **Scene.** Start from what the reader can observe: what they do, and what the system shows, says or writes. One short paragraph per event. Then name the internal part behind each event, in the system's own words. Define each internal name on first use in plain words. Introduce only names that later steps use.
2. **Question.** In one or two sentences, state the problem the mechanism solves in that scene: what the reader would see go wrong without it.
3. **Mapping.** Name the analogy, then give a three-column table, "What you observe" | "In the system" | "In the analogy", with one row for every actor, role and value that steps 4–6 use, including the failure and its fix. The analogy must preserve relations (order, who waits for whom, what is lost), not just names. Use only elements that have a row.
4. **Walk.** Trace the mechanism step by step: the normal path, then the failure, then the fix. In each step, first say what happens in the system, then add one line: "In the analogy: …". Every step, the fix included, is explained in the system first.
5. **Limit.** In one sentence, say where the analogy stops matching the system.
6. **Rule.** End with one sentence stating the general rule in the system's terms, now that those terms are defined.

Pick an everyday analogy whose parts and order match the mechanism one-to-one. If none fits, say so and explain without one, keeping steps 1, 2, 4 and 6.
